## Reflection

### 1. The Architectural Impact of Spec-Driven Development (Spec DD) in Sprint 4
In Sprint 4, Spec-Driven Development (Spec DD) proved to be an indispensable engineering paradigm. By formalizing `specification.md`, `api-spec.md`, `ui-spec.md`, and `tests.md` before authoring production code, we eliminated ambiguities and established clear architectural contracts:
- **Separation of Ticket Ownership vs Action Performer**: In previous sprints, tickets had a single owner. Lab 4 introduced `ActionTaken`, where multiple IT Staff and Administrators record discrete diagnostic actions on tickets owned by others. Spec DD codified this separation, ensuring that `performedById` is derived securely from the authenticated JWT session rather than user input.
- **The Authoritative Resolution Gate**: Requester autonomy and operational reality often clash in service desks. By codifying that Requester resolution indication (`problemAppearsResolved = true`) is purely advisory and leaves ticket status unchanged, while formal status transition to `RESOLVED` mandates at least one recorded action and a non-empty summary by authorized staff (`IT_STAFF` or `ADMINISTRATOR`), we prevented workflow invalidity at the API level.
- **Optimistic Concurrency Control (OCC) Semantics**: By establishing the `@updatedAt` token requirement (`expectedUpdatedAt`) in the contract, we ensured that concurrent updates return deterministic HTTP 409 responses, while the UI preserves uncommitted user input across state reloads.
- **Comprehensive Requirements Traceability Matrix (RTM)**: Every requirement mapped deterministically: Functional Requirement (FR) $\rightarrow$ Business Rule (BR) $\rightarrow$ Acceptance Criterion (AC) $\rightarrow$ Automated Test ID across all 53 planned tests, guaranteeing 100% coverage with zero blind spots.

### 2. AI as an Advanced Pair Programmer and Quality Multiplier
Collaborating with the Antigravity AI Coding Agent (Gemini 3.8 Flash) served as a force multiplier across the software development lifecycle:
- **Rapid Translation of Specifications to High-Fidelity Implementations**: The agent generated boilerplate-free, strictly typed TypeScript code that complied exactly with our predefined API contracts, Zod schemas, and Prisma queries.
- **Defensive Engineering & Edge-Case Catching**: When developing the status transition engine, the agent helped identify calendar rollover anomalies (e.g. JavaScript Date rolling February 31 into March 3) and sub-millisecond race conditions, leading to the implementation of strict ISO-8601 calendar regex validation and strictly monotonic timestamp advancement.
- **Responsive Layout Engineering**: Achieving zero horizontal overflow (`scrollWidth === clientWidth`) across 3 viewports on data-dense dashboards requires subtle CSS adjustments. The agent assisted in implementing responsive CSS grid transformations (5-column desktop $\to$ 2–3 column tablet $\to$ 1-column mobile stack) and isolated table overflow containers.
- **Preserving Absolute Human Authority**: While AI generated implementations rapidly, human engineering oversight maintained strict control over architectural boundaries, code reviews, and Git operations (preventing unauthorized push or merge actions).

### 3. Prompt Engineering, Defensive Constraints & Multi-Cycle Context Management
Sprint 4 provided deep insights into prompt engineering and context lifecycle management:
- **Vertical Issue Slicing**: Dividing the sprint into 8 isolated GitHub issues (Issues 20 to 27) with dedicated branch naming (`feature/lab4-*`) kept each agent invocation focused on a single responsibility, preventing context saturation and cognitive drift.
- **Constraint-Driven Specification Prompting**: Prompts that included explicit preconditions, HTTP status codes, error payload schemas (`"details": []`), and path references produced production-ready code with minimal revision.
- **Progressive Living Documentation**: Updating `reviewer.md`, `tests.md`, and `ai-use.md` incrementally as each PR was merged eliminated end-of-sprint documentation drift and ensured that recorded test counts matched automated test execution outputs.

### 4. Triangular Synergy: Developer, AI Coding Agent, and Peer Reviewer (@lephirada)
The triangular collaboration among the Developer, the AI Coding Agent, and Peer Reviewer (@lephirada) represented the highest standard of collaborative engineering:

  - Expanding responsive control collision checks to visible form inputs (`input`, `select`, `textarea`) with pointer-events filtering.

- **Rapid, Defensible Iteration**: With the AI agent assisting in implementing verified fixes and updating automated tests, developer response cycles were rapid and backed by clean test execution logs and green CI runs.
